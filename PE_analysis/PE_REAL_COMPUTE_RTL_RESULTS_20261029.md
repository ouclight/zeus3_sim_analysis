# 真实 AL1、MAC、OL1 本地逐周期仿真

日期：2026-10-29。RTL设计文件未修改；新增独立测试环境，采用本地Verilator 4.028，并用Icarus Verilog 10.3交叉验证单PE。没有wave、没有远端任务。

## 结论

已接入真实`pe518_top`，包含AL1 SRAM/坐标控制、16个ALU的实际BF16算术、OL1 FP32累加与输出。进一步将已有GDG/Hub/WL1返回链接入8个真实PE，形成一个硬件group的局部闭环。

在激活提前准备、输出始终接受、MC固定4拍服务延迟且每拍可返回一笔的测试边界下，真实PE不额外反压：256批权重首末接收跨度512拍，最后MAC接收到四组OL1输出分别为9/10/11/12拍。不存在模型自身必然要求861拍的现象。

这比此前固定`pe_ready=1`更强：此次ready来自真实AL1/MAC/OL1。实际观测在首末MAC之间激活valid、命令ready、流水ready、权重ready均持续为1。实际阻塞测试中MAC空拍全部是weight_valid=0，而非人为固定的PE行为。

这不证明远端861已经定位。尚未包含真实PEC激活供应、全核8group之间/双核竞争、实际MC控制器时序及跨时钟参数、group内8PE输出归约与完整L2返回、生产多指令调度。激活提前加载与输出恒ready是明确的隔离条件，本地RTL与冻结simv一致性也未闭合。

## 1. 数据、shape与数值验收

映射对应M1/N512/K4096、KC、w1/c32/k4、BF16、UEN=0。实际送入PE的三条64bit命令由`pe518_cmd_fifo.v`定义编码：TC=4095、TK=511、MTW=0、MTC=31、MTK=3、DFA/DFW=5、YMODE=1。

每个PE负责归约K的八分之一，每批读取8个激活，与16个ALU各自的8个权重相乘。256批=4输出组×64归约切片。每PE产生4批×16个FP32局部结果；8PE组共512个局部结果。这里没有将8PE局部和再次归约为group最终64个结果。

- 模式0：激活、权重均为BF16 1，每ALU每片段和为8，累加64片段，CPU可独立计算期望512（FP32 0x44000000）。
- 模式1：8个激活交替1/2；第a个ALU权重为2^(a mod 3)，期望768×2^(a mod 3)，分别768/1536/3072。用来验证实际SRAM读取、算术和不同ALU结果，而非仅检查非零或握手次数。
- AL1 ping/pong各写32个128bit字，合计64字1024B/PE。沿公开激活输入接口写入，不通过层级force装数据。激活就绪标记在各32字块末尾产生。
- 单PE每组64个输出逐位比较；联动组每个PE的全部64个输出逐位比较。计算控制/算术没有用行为模型代替。

这些为合成精确小数诊断，不是生产权重回放，也不是全范围浮点正确性验证。

## 2. 单PE：独立控制权重到达节拍

|供数间隔|数据模式|MAC批数|首末MAC跨度（含两端）|MAC间隔|内部拒收|最后MAC至最后OL1输出|
|---|---|---:|---:|---|---:|---:|
|1拍|全1|256|256|255次1拍|0|12拍|
|2拍|全1|256|511|255次2拍|0|12拍|
|2拍|交替激活/不同ALU权重|256|511|255次2拍|0|12拍|
|3拍|交替激活/不同ALU权重|256|766|255次3拍|0|12拍|

每拍一批是计算端压力测试，所需瞬时权重输入超过原GDG条件容量；不作为整机可持续供数的宣称。

跨度公式为最后事件减最早事件加1，因此256批、间隔2拍的跨度是511，并非512。联动模型另有一个C边界气泡，跨度才为512。

原始wait_weight统计包含权重开始供应前的预备时间，不能拿它直接与生产stall比较。内部拒收指weight_valid=1但ready=0，本轮单PE上述四组均为0。

额外执行三条相同命令，中间不复位DUT，每条重新经接口装载激活，均数值PASS、MAC跨度511、无内部拒收。测试驱动在命令间显式等待，因此不能把这个人为命令间隔当作生产稳态周期。

周期是局部testbench计数。无权重拍数包含正常的半速供数间隔，不全是可优化损失。这里每个窗口的周期数=256次MAC接收+无权重拍数。

4拍场景的首请求至最后OL1输出为527+12=539拍。它不是完整算子的耗时，不包括预先装载激活、PEC取指、全group归约及VP/ST等。

与先前理想PE接收端相比，三个场景的请求、权重接收跨度及阻塞计数完全相同。故在本测试条件下，真实计算端接入没有进一步降低权重持续吞吐。14/23拍场景会在真实GDG流控处触及15笔门限，此时MAC缺权重，而不是OL1反压。人工MC延迟不能作为远端MC实测值。

## 4. 对861原因的约束

1. 当前k4的普通OL1反馈，在真实RTL执行中可以被覆盖；不再只是缩减递归模型的推断。
2. AL1提前装好时能支持连续每拍读取和计算，未发现该shape强制的周期性激活停顿。
3. WL1与真实PE联动没有必然产生第三拍气泡；除了已知请求边界，能保持两拍一批。
4. 远端与本地的剩余差异应核查实际MC服务/时钟与共享竞争、真实PEC激活供应及输出接收/指令交接。不能宣称已排除真实环境中的激活或输出阻塞，因为这里主动理想化了这些边界。
5. 不应通过调人工MC延迟使输出恰好等于861来认定根因。本轮没有这样拟合。
