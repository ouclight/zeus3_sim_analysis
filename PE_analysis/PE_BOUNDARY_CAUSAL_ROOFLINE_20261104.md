# M1/k4长间隔的事件因果链及Roofline解释

本轮依据当前400MHz PE/MC、2GHz辅助时钟台架，不以历史861为拟合目标。没有重新改变RTL或等待参数：现有逐拍日志已记录WL1请求控制、MC命令与MAC握手，本轮新增可复现的关联脚本、九个边界逐拍CSV和定向统计。不能把此分析称作新跑过一轮RTL或完整SoC验证。

## 1. 首次定位：15/16拍来自MC跨物理行，中央边界还有请求气泡

每条MC lane每块依次读取512份权重，当前映射每物理行128份；每个MAC有效事件需要两份权重。因此每64次MAC跨一次物理行，256次MAC内部共有三次跨行。这里是MC行地址，不是数学矩阵的一行，也不是四个输出组彼此交接。

第一块lane0与group0事件如下。周期来自同一台架的逐拍计数。

| 边界（MAC编号） | 旧行最后CAS | 首个pre信号 | 新行第0列CAS | 新行第1列CAS | 前MAC→后MAC | 间隔 |
|---|---:|---:|---:|---:|---|---:|
| 64→65，row1→2 | 463 | 463 | 477 | 478 | 486→501 | 15 |
| 128→129，row2→3 | 668 | 669 | 683 | 684 | 691→707 | 16 |
| 192→193，row3→4 | 874 | 874 | 888 | 889 | 897→912 | 15 |

**全三块768个MAC事件均满足：MAC有效周期＝组成该操作数的第二份权重CAS周期＋23。** 这一固定传播差是本轮相关事件的观察值，不是credit往返时间，也不是另加在每个计算上的23拍开销。

所以长间隔没有在OL1或下游汇合处再次扩大：

- 第一边界：`478−463=15`，经过同样23拍传播后为`501−486=15`。
- 中央边界：`684−668=16`，传播后为`707−691=16`。
- 第三边界：`889−874=15`，传播后为`912−897=15`。

这是按权重顺序关联后的结果，不是比较两个无关时间点。所有lane数量/地址守恒和数值检查已由上一轮完成；本轮CAS细节记录仅lane0，不能声称逐lane均新增了同样监测。

## 2. 第一处15拍的逐拍过程

- c462：MC输入有效且ready，推进旧行末尾附近请求。
- c463：旧行col127发CAS，同时pre信号出现；MC请求ready降0。
- c463–468：MC ready=0，pre在c463–466为1，随后继续时序等待。
- c469：MC重新ready，接收后续请求。
- c470–476：新行打开/等待阶段，ready再次为0。
- c477：新行col0发CAS；c478：col1发CAS。
- 第二份数据经过既有返回、缓冲和整理后，c501出现下一次MAC有效。

真实`frame2array_aux.v`的R_DATA_LAST→R_PRECHARGE→R_TRP_CNT→IDLE及R_UP_RADDR→R_TRCD_CNT→R_DATA路径实施跨行控制。本台架tRP=6、tRCD=6；这些配置不是可随意相加到MAC节拍的独占耗时，状态转移、请求握手和流水重叠已反映在上述事件中。本轮未记录逐拍FSM状态，因此表中的具体ready/pre/CAS是观测事实，状态路径是结合RTL作出的解释，不伪称每拍FSM已采样。

## 3. 为什么中央多1拍

中央边界前存在一个可追溯的请求气泡：

| 周期 | 观测 |
|---:|---|
| 660 | WL1 reqv=1、reqr=1，地址392192 |
| 661 | `tcchange=1`、`ADDR_CNT_DELAY_FLAG=1`，reqv=0，而reqr=1 |
| 662 | reqv恢复，地址393216 |
| 667 | lane0 MC输入v=0，ready=1；旧行col126仍在CAS流水中 |
| 668 | MC输入v恢复；旧行col127发CAS，此拍pre仍为0 |
| 669 | pre才出现，进入跨行等待 |
| 675 | MC输入重新ready |
| 683 / 684 | 新行col0 / col1 CAS |
| 707 | 新组操作数MAC有效 |

`wl1_518_weight_ctrl.v:1359`定义地址延迟标志包含`tc_cnt_change_flag`，并明确用`!ADDR_CNT_DELAY_FLAG`门控请求有效；该标志的产生见同文件620行起的TC更新逻辑。此处不是下游不接收，WL1本身有一拍不发请求。

前后边界均在旧行最后CAS同拍出现pre，中间边界晚一拍；pre→新行col0均相隔14拍。结合请求气泡和MC v=0的传播，定位到“C分块地址切换与MC跨行控制交接”这一额外拍来源。三块相同气泡分别在661、1532、2403拍，三处中央边界均16拍，其余六个边界均15拍。

本轮没有通过强制信号消除该气泡做反事实实验；因此不宣称已验证删除某条RTL逻辑即可安全提速。MC内部EOF/状态逐拍信号未额外采样，若要做RTL级修复，还需补该局部接口监测。用户约束不改生产RTL，当前首先作为性能归因依据。

## 4. 871的分账与优化量级

`871=1+220×2+32×10+2×15+16+64=256+551+64`。

- 256：有效MAC拍；551：MAC窗口内缺权重拍；64：相邻MAC窗口之间的空拍。
- 32处10拍相对基本2拍增加256拍；前轮返回机制受控对照及credit统计支持其为持续窗口限制。
- 三次跨行相对基本2拍增加`13+14+13=40`拍，其中中央地址气泡只贡献相对另外两处多出的1拍。
- 64拍块间窗口尚不是完整模块级分账，不能统称为纯指令下发开销。

如果仅作预算、假设其它过程完全不变：移除中央额外1拍最多871→870；把三处跨行全部降为2拍最多871→831（约4.8%吞吐提升）；把32处10拍全部降为2拍则871→615。以上是孤立预算，不是已经实现或独立可加的优化收益，改变供数也可能改变交接与重叠。

## 5. 对PE Roofline的泛化边界

静态单核算术容量16384 FLOP/PE拍；条件权重容量8192 B/PE拍。稠密BF16、只按权重流量计算，M行共享权重时`Iw=M FLOP/B`，容量Roofline为`P≤min(16384,8192×Iw)`，交点Iw=2。

实际持续吞吐还要求：MC页服务能持续、在途窗口足以覆盖返回时间、各通路汇合及时、下游能接收、独立累加链足以覆盖反馈。布局和MTK解决其中一些条件，不改变全部条件。

| 量 | M1 local/k4 | M4 normal/w4 |
|---|---:|---:|
| 每块权重有效字节 | 4194304 | 4194304 |
| 每块FLOPs | 4194304 | 16777216 |
| 权重算术强度 | 1 FLOP/B | 4 FLOP/B |
| 算术容量下界 | 256拍 | 1024拍 |
| 条件权重下界 | 512拍 | 512拍 |
| 当前台架稳态 | 871拍 | 1177拍 |
| 算术容量利用比 | 29.39% | 87.00% |
| 有效权重量/稳态时间 | 4815.50 B/拍 | 3563.56 B/拍 |

M1有效权重吞吐相对8192容量约58.78%；不要与算术利用率29.39%混用。它不是物理总线busy率，因为分子只算有效权重，未含索引等事务。M4权重有效吞吐数值更低仍可算得高效，因为权重在四个输入行间复用。

`window/返回往返时间`可作为另一类请求吞吐约束，但不得把本轮CAS→MAC的23拍直接代入credit寿命公式。必须使用同一请求边界和同一时钟域测出的释放时间，还要区分流控暂停与下游停顿。更不能用M1的4815.50 B/拍画一条声称适用于所有shape的硬件带宽屋顶：它是该地址序列/配置/模型下的有效测量点。

建议顺序：优先改善能减少新权重需求的真实M维复用；M1保持数值合同情况下联合布局与独立输出链；针对持续供数窗口做可控请求/布局实验，但只有ISA允许且数值通过才是软件优化候选；MC跨行优化收益次之，需真实地址映射证据；不应为中央1拍改变整个归约算法。最终性能验收同时报告数值正确性、稳态/首尾、物理时间、权重流量口径和模型配置。
