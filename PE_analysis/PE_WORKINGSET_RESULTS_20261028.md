# Spread/Alias地址工作集对照结果：861 → 836 cycles

2026-10-28。Spread=`b2924754e9a3`；Alias=`fa19a2e0f6bc`。两组DONE，远端functional和VCS均严格逐位PASS，raw trace完整性及运行时隔离均通过。

**只改变权重索引，把完整块每条MC通路的地址工作集由512个word缩为16个word，两核完整N512稳态均从861降到836，每块减少25拍（耗时−2.90%，吞吐约+2.99%）。这给出了地址工作集/访问序列对当前持续性能有影响的直接A/B证据，但尚不能唯一归因到MC bank/row、缓存或返回窗口。**

## 1. 实验控制与验收

固定M1/K4096/N8448、双核，各核8条N512和1条N128；完整块local V-cache/page128、KC、w1/c32/k4。沿用已验证的I同步，首VP等待本核最后PE完成。

为了让地址别名不改变数学结果，诊断将每个完整tile的首K128页重复32次。Spread依次访问32个物理副本；Alias的32个逻辑索引都指向第一个物理副本。尾块没有改变索引或payload。两组都保留所有副本，权重文件各34 MiB/core，既没有压缩文件，也没有改变计算量。

| 验收项 | 结果 |
|---|---|
| 两组binary、输入、输出初值、golden | 相同 |
| 两核权重payload及文件长度 | 相同；差异只在完整块有效索引项 |
| remote functional | Spread 1a762b7e3269、Alias c671b38e2303，严格逐位PASS |
| VCS命名输出output_ptr | 各33792 B，实际文件与golden逐字节相同 |
| 数值误差 | max_abs_diff=0、cosine=1 |
| post-pass检查 | 两组PASS |
| 每核事件数 | 9 PE、18 VP、9 ST |
| trace | sealed，funnel/writer clean，无overflow/truncation |
| 硬件/服务身份 | 六项digest一致，并与C/I任务一致 |
| 环境 | MC模式、400 MHz |
| 权重加载 | 成功，direct_ldg_write，两核合计71303168 B |

这是合成精确小数诊断，不能直接当作生产模型可实施的权重压缩方案。observer依然draft、metric_eligible=false；全局时间取物理alignment，不采用meta.actual_cycles。

## 2. 结果：两核、七个稳态间隔全部一致

| 指标 | Spread core0/core1 | Alias core0/core1 | 改变 |
|---|---:|---:|---:|
| 首PE事件生命周期 | 953 / 953 | 935 / 935 | −18 |
| 7个完整N512完成间隔 | 全部861 / 全部861 | 全部836 / 全部836 | 每个−25 |
| N128尾块完成间隔 | 301 / 301 | 294 / 294 | −7 |
| 首PE start至末PE end | 7281 / 7281 | 7081 / 7081 | −200 |
| 双核物理对齐全算子周期 | 9919 | 9719 | −200（−2.02%） |
| 首VP−本核最后PE完成 | +32 / +32 | +32 / +32 | 不变 |
| 首ST−本核最后PE完成 | +251 / +251 | +251 / +251 | 不变 |

400 MHz下全局时间24.7975 µs → 24.2975 µs，减少0.5 µs。PE跨度变化核算为`18 + 7×25 + 7 = 200`。尾块本身未改索引，完成间隔仍减少7，表明不能把每项差值简单当成本条命令独立的存储访问成本：前序状态、流水衔接或排队也会影响边界。

Spread与之前I任务的PE start/end及9919全局周期完全复现，说明本次重复页合成数据没有改变基线节拍。Alias是稳定的逐块变化，不只是启动快25拍或末尾偶然快一次；但只有一对远端运行，不能据此统计跨运行方差。

## 3. 隔离仍然有效，排除VP/ST混杂

两组均满足：本核首VP/ST在最后PE完成之后，且每核7个完整块稳态窗口内无本核VP/ST。

进一步依据trace_time_alignment将两核映射到同一物理时间，检查任一核的VP/ST：两组所有完整块稳态窗口的跨核重叠计数也全部为0。因此836不是后处理重叠变少造成的。

这仍是核内mail屏障，不是全芯片全程屏障；结论限定完整块稳态窗口。PE内部结果返回/L2输出没有被移除，不能把此实验称作纯MAC仿真。

## 4. 它证明了什么，没证明什么

### 4.1 地址工作集确实有可测贡献

唯一输入变化是索引引用方式，逻辑操作数及其计算顺序相同，payload文件字节相同。因此在当前环境下，物理权重地址序列改变可以使持续节拍改善25拍。此前只有“地址连续不保证快”的结构可能性；现在增加了一个正向A/B证据。

不宜再把“权重存储地址怎么组织都无关”作为结论。但也不宜把25拍确定命名为DRAM换行等待：没有内部存储命令、缓存命中或返回计数。

### 4.2 主要差距仍存在

按相同逻辑有效工作量计：

```text
Spread：4 MiB / 861 ≈ 4871 B/cycle，条件容量占比512/861=59.47%
Alias ：4 MiB / 836 ≈ 5017 B/cycle，条件容量占比512/836=61.24%

对条件512下界的差距：349 → 324 cycles
此次净改善占原差距：25/349 ≈ 7.16%
```

这里按完整逻辑权重使用量计吞吐；Alias有权重重复访问，不是已测出的物理MC传输字节率。当前没有证明512一定是该实际运行配置可达到的持续下界。

所以，缩小工作集有小幅收益，但远未解释或消除全部持续成本。剩余324也不能命名为“324拍MC等待”。

### 4.3 不能声称带宽需求已减少32倍

工作集从512降到16 word，是不同地址数量减少32倍，不是请求数或实际读取字节数自动减少32倍。已核查的Hub读缓存深4，而重复循环包含16个地址；真实返回链testbench在这条循环下两组仍各产生512笔/MC请求。

该testbench支持“此循环未在所测4槽缓存中产生流量下降”，但不是远端VCS内部请求数测量。836可能与MC服务局部性、返回调度、窗口及有限缓冲的相互作用有关；不能用这次结果直接判断某个具体模块。

### 4.4 不能把Alias直接用于正常模型

正常模型中不同K页的权重通常不同。把它们全部指向第一页会改变点积结果。本次重复页是为了保留数学一致性而构造的诊断条件。生产可迁移方向只能是正确重排/分配真实数据后是否改善访问局部性，需要新的数值与性能验证。

## 5. 当前根因范围和下一步优先级

1. **VP/ST并发：**C/I已经排除为本案例861稳态限制因素。
2. **地址局部性：**本次证实存在25拍/完整块的端到端贡献；它不是剩余主要差距的充分解释。
3. **持续请求/返回/接收闭环：**继续优先核查MC服务间隔、在途额度及Hub汇合/PE接收反压。AL1与OL1输出侧仍未通过直接计数唯一排除。

下一项更有区分力的实验应先确认干预是否真的改变硬件流量：核查ISA可表达的小工作集与请求次序，在真实返回链testbench中使它能命中已知缓存，并计数证明“逻辑计算不变，MC请求减少”。只有能构造成功，再考虑远端VCS。不能直接把当前16-word Alias继续称作带宽减量实验。

与此同时应核查冻结运行的MC配置和返回额度实际时钟/服务边界。将未知MC延迟设成23拍、拟合出近似836或861，不是因果证明。本次不修改RTL、不自动提交额外任务。
