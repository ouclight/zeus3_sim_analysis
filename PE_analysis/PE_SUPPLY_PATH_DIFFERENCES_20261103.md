# M1持续供数与M4复用：生产路径差异核查

日期：2026-11-03。接续[单核8-group M4对照](PE_M4_NORMAL_X8_COMPARISON_20261103.md)。本轮为源码审计、既有数据核对及一个生产GDG仲裁单元仿真；没有重新跑完整PE模型，没有修改生产RTL，没有拟合861。

## 1. 本轮结论

M4在本地1177拍与远端吻合，但其块内权重一直有效；该条件并未检验供数链在M1持续消耗新权重时的极限。已定位两个具体覆盖差异：

1. 当前lane跳过生产GDG读写仲裁器。然而新增纯读单元仿真证明默认分支没有额外接收空洞，应降低该项优先级，不能仅凭模块缺失归因。
2. 当前PHY返回DW FIFO行为适配器与交付DW控制器的empty生成机制不相同。这是可落到代码的时序核对项，优先于继续任意增加PHY延迟。尚未完成原DW整体等价仿真，不能宣称它贡献了多少周期或解释了861。

仍缺生产寄存器/宏/时钟配置和原厂PHY/DW完整依赖，故291周期差距尚未分解。

## 2. 纯读GDG仲裁：实际运行排除固定限速假设

生产路径：`code/rtl/gdg/gdg_unit/gdg_unit.v`读forward_pipe→`gdg_unit_rw_rr_arbiter`→`gdg_axi2frame`。

台架`artifacts/pec_m4_normal_x8_20261103/lane.sv`包含读forward_pipe，但直接构造`rr_data`送入`gdg_axi2frame`，省略仲裁器。生产默认分支的读地址没有再右移5位，构造帧与台架一致。

新增测试直接实例化原始`gdg_unit_rw_rr_arbiter.v`和`z518_l2_round_robin_arbiter.v`，写请求固定0。每个有效周期检查输出valid、ready及完整286-bit请求帧。

| 条件 | 测试周期 | 接收数 | 检查 |
|---|---:|---:|---|
| 读valid持续为1，下游始终ready | 4096 | 4096 | PASS，每拍一笔 |
| 读valid持续为1，下游每11拍ready7拍 | 4096 | 2608 | PASS，无额外限速 |
| 间歇读valid，下游始终ready | 4096 | 2341 | PASS，帧正确 |

后两项是协议单元测试的确定性激励，不是生产时序模型，不用于拟合861。无请求时ready不要求与下游相同。

材料：`artifacts/pe_supply_path_audit_20261103/arbiter_probe.sv`、`arbiter_probe.log`、`run_probe.sh`。仅覆盖未定义`GDG_UNIT_REW`的默认分支，没有引入后台写入。生产若启用该宏或确有写请求/伪读，需要单独对齐证据；不凭空加入竞争流量。

## 3. PHY返回FIFO：真实可见的建模差异

MC的`frame2array_aux.v:820`实例化`DW_fifo_s2_sf`：depth11，push_sync=2，pop_sync=2，PHY rdrdy_n为写时钟、MC clk为读时钟；每个PHY返回边沿写入，非empty时自动读出。

现有适配器位于`pec_m4_normal_x8_20261103/lane.sv`末尾：

```verilog
ws[0] <= wc;
ws[i] <= ws[i-1];
assign pop_empty = rc == ws[nstages-1];
assign data_out = mem[rc % depth];
```

交付文件`MC_2025_05_30_release/common/rtl/DW_fifoctl_s2_sf.v`则包含：

- 469行：`DWsc_sync`同步写指针；
- 438～450行：根据读请求和同步写指针计算下一读地址、下一占用计数；
- 483～484行：读时钟寄存读地址和占用计数；
- 521、532行：由寄存后的占用计数生成`pop_empty`。

因此，不能仅因两者都写着“pop_sync=2”就视为逐周期等价。同步完成后的empty可见时刻、空转有数据的恢复、指针环回与full处理都需要对齐。

这不是已经证明的“每笔固定多一拍”：持续非空时仍可能每拍出数；额外可见延迟是否通过15笔credit窗口降低持续吞吐，必须闭环验证。M4复用可掩盖某些供数延迟，M1更敏感，但这仍是待验证作用路径。

依赖核查：本地有`DW_fifo_s2_sf.v`和`DW_fifoctl_s2_sf.v`，在已复制的`code/Zeus518`树中未找到`DWsc_sync`、`DW_ram_r_w_s_dff`文件。因此不能把现有适配器称为完整原厂DW实现，也不能声称单凭当前交付包装文件已可直接替换运行。可以先核查同步控制并做带明确边界的单元对照，但自写缺失依赖仍然是模型。

另有工具陷阱：当前适配器读取`FIFO_SYNC`使用空分支`if($value$plusargs(...))begin end`，前轮已发现Verilator4对此可能消除副作用。后续若做同步级数对照，必须检查实际生效值；本轮没有执行该参数扫描。

## 4. credit满不等于根因

前轮实际数据中，M4的credit halt、返回反压计数远高于M1，但M4块内权重始终有效。其含义是权重消费较慢，上游可以被正常反压；不能据此认定credit限制了计算。

生产与台架目前均使用原`gdg_flowctrl.v`，读窗口阈值15；credit在Core域按请求送出与数据接收更新。窗口值本身没有发现台架遗漏。

后续要检查的是：请求入窗→MC接收→PHY写FIFO→FIFO出数→ECC→GDG返回→credit释放，各边界的实际时刻是否一致，而不是把15/某个猜测延迟当作测量结论。

## 5. 后续核查优先级

| 优先级 | 项目 | 本轮判断与下一步 |
|---|---|---|
| 1 | DW返回FIFO及PHY返回采样 | 明确存在实现差异；先核对控制器可见时序、缺失依赖和生产版本，再做单MC闭环，最后同时回归M1/M4 |
| 2 | 生产MC/PE时钟与配置 | 本地固定400/400MHz、profile1；需要实际构建/初始化证据，不能由M4周期吻合倒推全部一致 |
| 3 | 完整MC控制环境 | 本地仅接读控制与ECC，初始化完成条件、刷新、后台流量未覆盖；只按真实配置接入，不人工制造竞争 |
| 4 | GDG读写仲裁 | 默认纯读单元已验证不额外限速；有宏或混合请求证据时再升级 |
| 已覆盖 | 单核8-group、32 MC/group、Hub响应汇合、真实计算ready | 这些已参与前轮；不能再笼统列作完全未仿真的模块 |

本轮没有新证据支持“两个Core必然竞争同一条权重接口”；仍需生产连接版本核对。也没有证据表明M1的861是MTK4的必然计算成本。

## 6. 验收原则

下一次模型修正需有源码或配置依据，并同时验证：M1能否解释远端差距、M4是否仍接近1177、全部数值和请求/返回/credit守恒。若只把M1调到861、却无法解释M4或采用任意延迟，不视为根因定位。
