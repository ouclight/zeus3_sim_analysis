# M4 normal与M1 local：已校准单核8-group RTL对照

日期：2026-11-03。

**本地M4 normal/w4/c16/k1复现1177-cycle稳态，与历史VCS `4182cb8a1e2f` 的代表稳态一致。相同MC条件下，M1 local/w1/c32/k4复跑仍为570 cycles，而历史远端为861。** 本轮验证了M4高算术利用率及真实权重复用机制，也表明现有模型对M1的剩余偏差尚未消除；周期吻合不等于整个生产环境已经匹配。

## 1. 配置、范围及证据

完整材料：[artifacts/pec_m4_normal_x8_20261103](artifacts/pec_m4_normal_x8_20261103/)。

- 三条连续PE指令，每条数学形状为`A[M,4096] × W[512,4096]^T`。
- 单核8 group、64 PE、256条MC通路；真实PEC、WL1指令/索引/格式控制、AL1、MAC、OL1、L2，以及前轮MC读控制/GDG请求返回与credit链。
- MC profile=1：tRAS/tRP/tRC/tRCD/tRTP/tWR/tWTR/tRTW = 13/6/19/6/1/6/3/4；PE/MC均400MHz；命令驱动PHY模型tAA=7ns。
- PHY仍是行为模型，原厂DW返回FIFO仍由前轮适配器替代；刷新关闭，无后台请求。本次没有重新编译Triton、修改生产RTL或提交远端任务。
- M1复用已校准模型的可执行文件重新运行。M4在独立目录构建；原台架94个来源文件哈希均未改变，见`baseline_integrity.json`。
- A、W为BF16全1，独立数学预期为FP32 4096；M4四行位于不同的L2地址。全1数值不能检验任意元素置换；所有通路另有逐笔物理地址、数量、返回顺序/数据断言。
- 这是控制级三指令诊断，不是完整生产kernel二进制回放。权重及L2地址重定位，未执行VP/ST。normal不启用索引，未发送无效用的WBS/index描述符；不能声称全部命令字与历史程序相同。

历史配置依据：[M2/M4布局对照记录](PE_ROOFLINE_ANALYSIS_20261022.md#16-m2m4局部v-cache任务完成本轮mtk1配置略慢于normal2026-10-27)及`artifacts/m2_m4_local_vcache_20261027/m4_normal/kernel.disasm.S`、`instruction_audit.json`。

M4驱动不仅改变MTW/MTK，还设置TW=3、TC=4095、TK=511、WC=4095、SC=4095、DC=511、WSTMOD=0、WIDXEN=0；MTW/MTC/MTK字段为3/15/0，表示有效4/16/1。M1的V-cache WC=511不能直接用于normal。实际下发8个命令字与`command_audit.json`逐字一致。

## 2. 数值与守恒检查

两组进程退出码均0，检查全部通过。

| 检查（三条指令合计） | M1 local | M4 normal |
|---|---:|---:|
| 每个PE的MAC握手数，检查全部64 PE | 768 | 3072 |
| 每条MC的请求/MC接收/CAS/PHY返回/ECC/credit释放/下游接收 | 各1536 | 各1536 |
| 检查的MC通路数 | 256 | 256 |
| PEC读取激活次数 | 192 | 3072 |
| L2写出及读回拍数（每拍32个FP32） | 48 | 192 |
| FP32输出逐元素正确数 | 1536 | 6144 |

每lane每块512笔，每笔32B：`256 × 512 × 32 = 4 MiB`有效权重。三块两组均12 MiB。实际MC物理地址每块均检查为128～639，WL1内部请求序列每块均检查为`0x20000 + i×1024`，i=0..511。

M4每个group新增FIFO复用计数：**3072次完整分发、768次FIFO弹出，精确4:1**，八组全部通过。对应生产RTL：`wl1_518_weight_data_format.v:1130–1147`，MTW计数到头才执行`weight_fifo_rd_en`。MTK输出分组不提供这种跨输入行权重复用。

## 4. MAC窗口内的直接周期证据

窗口取每块第一次MAC握手至最后一次MAC握手，包含两端。各group的PE0逐拍日志提供以下结果；八组相同。全部64 PE还分别检查MAC总数及全程拒收统计。

| 后续完整块窗口 | M1 local | M4 normal |
|---|---:|---:|
| 窗口长度 | 550 | 1157 |
| MAC有效拍 | 256 | 1024 |
| 权重无效拍 | **294** | **0** |
| 激活无效拍 | 0 | **133** |
| 命令不就绪拍 | 0 | 0 |
| 计算流水不ready拍 | 0 | 0 |
| 权重有效但未接收拍 | 0 | 133 |
| OL1输出有效但下游未接收拍 | 0 | 0 |

这些信号一般允许重叠，不应普遍相加；本次窗口的具体取值使MAC空拍能够直接归入对应无效条件。M4全程weight-blocked计数还包含窗口外启动/交接，不能与表内133混用。

### M4：块内连续计算，间隔性等待激活

每个块MAC相邻握手间隔分布为：1016次间隔1拍、7次间隔20拍。即1024次MAC被分为八段，每段128次连续MAC；七处间隔各含19个无MAC周期。

因此：

```text
块内MAC窗口 = 1024个MAC有效拍 + 7×19个激活无效拍 = 1157
连续块稳态 = 1157 + 20个块间无MAC拍 = 1177 cycles
```

group0首/末MAC分别为602/1758、1779/2935、2956/4112。PEC完成点间隔和首次MAC间隔均1177。

这里133拍已由信号确认是AL1→MAC激活无效，而不是权重没来、OL1输出反压或计算流水拒收。**尚未细分这133拍在PEC读请求、L2返回、激活CDC和AL1切换各自占多少；不能直接全称为外部激活带宽等待。** 块间20拍也是观测到的整体交接空档，不将其指定给某个单模块。

### M1：持续新权重需求，计算侧没有阻塞

后续每块256个MAC的相邻间隔为252次2拍、3次15拍：

```text
块内MAC窗口 = 256个有效拍 + 294个权重无效拍 = 550
连续块稳态 = 550 + 20个块间无MAC拍 = 570 cycles
```

M1首块受启动/预取影响，窗口544拍；后续为550。此处“缺权重”描述PE输入信号，不自动等同于MC某一环节堵塞；前轮已经检查长空档与本地MC行边界服务相关。

## 5. 供数链为何在M4表现不同

M4每份FIFO权重连续服务四行，下一份权重的准备时间更宽松。在本轮M4的三个MAC窗口内，权重始终有效，说明这套供数链已足以供满M4的有效计算阶段。

反过来，M4的GDG返回和credit等待计数比M1更高，不是更低。例如lane ID32：

| 全程计数 | M1 | M4 |
|---|---:|---:|
| MC拒收 | 150 | 150 |
| credit halt | 165 | 2006 |
| 返回缓冲阻塞 | 22 | 2016 |
| 下游接收阻塞 | 22 | 2018 |

全部256 lane累计MC拒收两组均38400拍（各lane相加，不是全核墙钟时间）。M4全程更长、权重消费更慢，返回缓冲与在途窗口会更久占用。这些累计等待不代表它们限制了MAC：MAC窗口内没有缺权重，说明其上游有余量。**不能只看到credit满或返回被反压，就将它认作性能根因。** 原始所有lane计数保留在results.json。

## 6. 对861问题的推进与未解决边界

1. 已实测复现M4的1177与87%折算效率，不再只是用“MTW可以复用”解释。
2. 本地M1/MTK4没有不可避免的861下界；真实计算模块在当前供数条件下可达570，持续窗口未出现OL1输出阻塞或流水拒收。
3. M4高效不能证明生产供数链足够支撑M1：M4使用四倍算术工作量摊薄相同权重传输，并且要求的新权重到达频率更低。
4. M4周期吻合不证明本地MC/PHY/DW模型完全等同远端。M4对新权重供给的压力较低，一些供数差异可能被权重复用遮蔽。
5. 远端M1的861与本地570仍相差291拍。本轮没有把这291拍归因到具体环节，也不通过人为加延迟拟合。

下一步更有价值的是对齐生产M1路径中高持续请求率时的实际接收/返回时序、DW返回FIFO及跨域配置、初始化/刷新/后台请求和实现版本；用已通过的M4对照作为约束，任何模型修正都应同时解释M1与M4。若进一步拆解M4的133拍，应沿PEC→L2→激活CDC→AL1的真实信号追踪，不先改变MC服务延迟。
