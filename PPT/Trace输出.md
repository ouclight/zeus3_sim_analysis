# 左侧：输出及其作用

```
                NPU指令执行
                     │
      ┌──────────────┼──────────────┐
      ▼              ▼              ▼
   结果输出        过程输出        分析输出
      │              │              │
 Golden Compare   Instruction     Conflict Report
 Memory Dump      Executor Trace  Timing Statistics
 Output Data      Launch Status   Memory Effect
      │              │              │
      └──────────────┼──────────────┘
                     ▼
          结果判断 + 问题定位 + 优化分析
```

可以将输出分成五类：

| 输出类型 | 主要内容                          | 带来的功能                     |
| -------- | --------------------------------- | ------------------------------ |
| 结果输出 | Output、Golden Compare            | 判断当前Case的最终结果是否正确 |
| 状态输出 | 寄存器、L2、DDR Dump              | 查看指令执行后的架构状态       |
| 过程输出 | Instruction、Core、Executor Trace | 还原执行路径和指令等待关系     |
| 分析输出 | Memory Effect、RAW/WAR/WAW报告    | 检查内存访问是否具有可证明顺序 |
| 系统输出 | Launch状态、错误信息、Snapshot    | 支持Runtime联调和失败现场保留  |

如果页面空间允许，可增加：

| 输出类型 | 主要内容                           | 带来的功能                     |
| -------- | ---------------------------------- | ------------------------------ |
| 时序输出 | 发射Tick、完成Tick、Latency、Stall | 分析抽象调度、并行度和关键路径 |

# 右侧：输出能力与边界矩阵

这是本页重点。

| 仿真输出             | 可以说明                         | 不能直接说明             |
| -------------------- | -------------------------------- | ------------------------ |
| Golden Compare通过   | 当前输入下，最终结果与Golden一致 | RTL和芯片一定正确        |
| Golden Compare失败   | 仿真结果与Golden存在差异         | 一定是编译器错误         |
| Register/Memory Dump | 某时刻的架构可见状态             | RTL内部寄存器和信号状态  |
| Instruction Trace    | 当前动态路径执行了哪些指令       | 未执行分支是否正确       |
| Executor Trace       | 指令如何分派、等待和完成         | RTL每一级流水状态        |
| 无Conflict报告       | 已记录的重叠访问存在可证明顺序   | 所有输入和并发交错都安全 |
| RAW/WAR/WAW报告      | 依赖图不能证明相关访问有序       | 硬件一定产生错误结果     |
| Timing Trace         | 当前Cost模型下的调度和关键路径   | 未校准时的真实芯片周期   |
| Launch Completed     | 仿真任务正常结束                 | 输出数值一定正确         |
| Launch Failed        | 执行或诊断条件失败               | 根因一定属于某一个团队   |
| Snapshot             | 保留部分内存和Launch现场         | 可完整恢复运行状态       |

# 各类输出的典型使用方式

## 1. Golden Compare：判断结果

回答：

> 最终输出是否与预期一致？

适合：

- 编译器功能回归；
- 算子Case验证；
- Python/C++结果比较；
- RTL或硬件Golden对照。

边界：

> Golden一致只能说明当前输入和当前模型下结果一致，不证明所有动态路径正确。

## 2. Memory Dump：查看状态

回答：

> 指令执行后，寄存器和内存里是什么？

适合：

- 检查输入是否正确加载；
- 检查PE、VP输出位置；
- 查找地址或Stride错误；
- 判断数据从哪一步开始异常。

边界：

> Dump反映架构可见数据，不反映RTL内部FIFO、Pipeline和握手信号。

## 3. Trace：还原过程

回答：

> 执行了哪些指令，为什么等待，什么时候完成？

适合：

- 跟踪PC和控制流；
- 检查Executor分派；
- 检查Mail收发；
- 观察多Executor重叠；
- 定位死锁和异常停顿。

边界：

> Trace是指令级或抽象Timing Trace，不是RTL信号波形。

## 4. Conflict Report：检查依赖

回答：

> 两条重叠内存访问之间是否存在可证明的先后关系？

适合：

- 发现缺少Mail；
- 检查跨Executor访问；
- 定位RAW、WAR和WAW；
- 作为CI诊断或失败条件。

边界：

> 报告的是“模型无法证明有序”，不是“硬件一定冲突”。

## 5. Timing输出：分析性能

回答：

> 当前Timing模型下，指令如何重叠，时间消耗在哪里？

适合：

- Executor利用率分析；
- Mail和Barrier等待分析；
- 调度方案比较；
- 抽象关键路径分析。

边界：

> 未完成RTL或芯片校准前，逻辑Tick不能直接作为芯片绝对周期。

# 一页PPT可直接使用的精简文案

## 仿真器输出：从结果判断到问题定位

> 仿真器通过结果、状态、过程和分析输出，支持功能验证、问题定位、依赖检查和抽象时序分析。

| 输出                       | 提供的功能                       | 使用边界                    |
| -------------------------- | -------------------------------- | --------------------------- |
| Golden Compare             | 判断当前Case结果是否符合预期     | 不能证明RTL或所有输入正确   |
| Register/Memory Dump       | 查看架构可见状态和数据位置       | 不包含RTL内部状态           |
| Instruction/Executor Trace | 还原控制流、分派、等待和完成过程 | 不等同于信号级波形          |
| Conflict Report            | 检查RAW/WAR/WAW是否有序          | 报告冲突不等于硬件必然出错  |
| Timing Trace               | 分析逻辑周期、流水重叠和关键路径 | 准确度依赖模型和硬件校准    |
| Launch Status/Error        | 支持Runtime任务管理和错误定位    | Completed不等于数值验证通过 |
| Snapshot                   | 保存失败时的内存和Launch现场     | 不是完整运行检查点          |

中心图：

```
指令执行
   │
   ├── Output / Golden ─────► 结果是否正确
   ├── Dump ────────────────► 数据从哪里开始异常
   ├── Trace ───────────────► 指令如何执行和等待
   ├── Conflict ────────────► 依赖关系是否完整
   └── Timing ──────────────► 时间消耗和关键路径
```

底部边界声明：

> 仿真器输出反映当前模型、当前输入和本次动态执行路径下的架构行为；不能自然外推为RTL信号等价、全路径正确或芯片性能准确。

汇报时可用一句话收束：

> Golden告诉我们“结果是否一致”，Dump告诉我们“数据错在哪里”，Trace告诉我们“过程如何发生”，Conflict和Timing报告帮助解释“为什么发生”；但所有结论都受仿真模型和动态执行范围约束。
